# Self-contained instances requirements

## Baseline

[Phase 14](../2026-11-07_instance-editing-and-recomputation/plan.md) provides atomic in-memory edits and returns final derived statistics separately from the instance. The [current v1 contract](../../data_contracts/contracts.md) persists source values and effect entries. At the starting commit, the roadmap scheduled library selection at Phase 15 and planned to recompute derived results when opening saved instances in Phase 16.

## Planning requirements

- **R1. Sheet state.** For character and monster instances, store all final derived statistics alongside editable source values and the existing entry/effect snapshots. Each final value already incorporates its applicable modifiers. For example, an Ork with Toughness 45 and Unnatural Toughness x2 stores a Toughness Bonus of 8. The effect snapshot retains the multiplier and its source. Keep direct overrides of derived values outside the first milestone.
- **R2. Calculation lifecycle.** Initialize final statistics at creation. When a source or effect edit changes calculation inputs, evaluate from the edited source and entries, then publish both source and final values together. A failed edit preserves the last valid instance and its final statistics. Preserve stored results for no-op and metadata-only edits. Normal load, display, and save consume the recorded values without evaluating formulas or reapplying effects. Structural and compatibility validation remain separate from evaluation.
- **R3. Dependencies.** Retain exact system and template references. Resolve the exact definitions for creation and enable editing only after exact resolution. Use one validated snapshot and one presentation path for both editable and read-only sheets. Persist the minimum presentation metadata needed to render the saved sheet independently of the definitions. If the exact versions are unavailable, display the stored sheet read-only, explain the missing dependency, and disable edits and saves. Invalid snapshots fail with diagnostics. Reopening never rewrites the source file.
- **R4. Sequence.** Insert Self-contained instance sheets as Phase 15 to specify and implement the revised instance contract and domain lifecycle before filesystem work. Move former Phases 15–21 to 16–22 in the same order. Retain selected-system-only loading and catalog lifetime requirements in Phase 16. Phase 17 reads and validates stored results, Phase 18 writes them safely, and Phases 19–22 display, update, round-trip, and verify them in the desktop workflow. Preserve completed phase history and the separate feature-library commitment.
- **R5. Handoff.** Phase 15 specifies the exact result representation, schema version and compatibility policy for existing source-only data, and what can be validated about stored results without running formulas. Older data must have an explicit supported path or an actionable error. Normal loading must never silently recalculate, upgrade, or rewrite a file. Any supported conversion that materializes missing results is a separate, explicit operation. Update the normative contract, schemas, domain guides, and fixtures during implementation. Later phases specify their filesystem and interface checks.
