## Execution evidence - 2026-10-29

Environment: Windows x64, Node 26.13.0, npm 12.2.1; existing locked dependencies unchanged. No new package or toolchain versions were installed.

- **V1 Passed:** npm run typecheck and npm run format:check exited 0. Strict checking covers main, preload, shared contracts, renderer and tests. Formatting checks include the phase documents.
- **V2 Passed:** npm run package exited 0 using Forge/Webpack. Produced out/RPG Buddy-win32-x64/RPG Buddy.exe. Inspected resources/app.asar with @electron/asar listPackage: main index.cjs, renderer HTML/JS and preload.cjs present; test fixture and test directories absent.
- **V3 Passed:** final npm run test:smoke reported `6 passed (4.1s)`. Development launch passed in 2.4 seconds and packaged launch in 963 ms. Both modes display app version 0.1.0 and runtime versions through the bridge; packaged values match app.getName(), app.getVersion() and process.versions from the actual main process. Bridge keys contain only getApplicationInfo. Renderer require/process are undefined, child iframe has no bridge, window.open returns null and attempted external navigation sends no request and retains the trusted document. Reload restores information; narrow 360px viewport with doubled text has no horizontal overflow. Both close cleanly with exit 0 and no normal-flow renderer/asset errors.
- The two contract/adapter cases run in each project: valid request succeeds; null, arrays, strings, missing/wrong version, extra keys and wrong argument count fail; missing owner, destroyed owner, wrong webContents, missing/child frame and wrong URL fail without reading info. Unexpected exceptions, invalid responses and transport rejections return safe failures without private error text.
- Additional packaged integration uses an automation-owned foreign BrowserWindow with a test preload: real IPC returns FORBIDDEN. Registering that test preload temporarily on the application session permits raw requests from the trusted main frame; five malformed argument combinations return INVALID_REQUEST, and the normal UI still displays info. The fixture registration is removed afterward. Removing the handler and reloading displays the safe role=alert message. This failure is deliberately injected only by automation; the shipped bridge has no raw invoke method.
- **V4 Passed:** inspected renderer/preload/main boundaries, fixed channel and payload, sandbox/context isolation, denied popup/navigation/webview behavior, exact three-document phase folder, updated README and roadmap; git diff --check passed. Visually inspected the full-page packaged screenshot at 360px with doubled text: wrapped version labels and values remain readable, with no horizontal clipping. Loading status and error alert semantics are present in source; no new controls or keyboard traps are introduced. Contract fixtures, dependencies and lockfile are unchanged.

Generated screenshots and diagnostic JSON live under ignored test-results/ and are replaced on rerun. Durable evidence is this record plus the reproducible checks. Renderer navigation cancellation can leave Playwright's navigation barrier pending: the test checks the live document with CDP, confirms no external request, stops loading and reloads before continuing. It does not relax the application's navigation policy.

Failures found and corrected before completion: development preload initially loaded unsupported Node shims from the dev-server client; initial process.isMainFrame guard was replaced with the browser main-frame identity check; packaged raw Forge URL comparisons rejected encoded Windows file URLs. The tests now cover the corrected behavior. The first navigation test used a data URL blocked by Chromium itself; it was replaced with an HTTPS attempt to verify the application policy.

Reference guidance: [Electron sandbox behavior](https://www.electronjs.org/docs/latest/tutorial/sandbox), [context isolation and narrow APIs](https://www.electronjs.org/docs/latest/tutorial/context-isolation), [IPC sender validation](https://github.com/electron/electron/blob/main/docs/tutorial/security.md), and [Forge Webpack preload configuration](https://www.electronforge.io/config/plugins/webpack). Installed Forge/Electron source and typings were also inspected for the exact API version.

Limitations: user keyboard/screen-reader/OS-zoom walkthrough and non-Windows launches remain unperformed. Existing dependency audit findings documented by Phase 3 were not re-audited or changed. Phase 5 diagnostic logging and game features remain unimplemented.

## Shell test refactor - execution evidence, 2026-10-29

Status: Passed. This section supersedes the six-test count above; the earlier implementation evidence remains historical.

- npm run typecheck passed. npm run test:smoke reported **12 passed (9.3s), 2 skipped**. The development-only skips explicitly cover packaged main-process automation; both cases previously ran only inside the packaged branch of the monolithic test. Development launches took approximately 2.2 seconds each; packaged launches took 351–510 ms each. No application source, build configuration, dependencies or lockfile changed in this refactor, so the existing production package was reused.
- Shared fixture: tests/smoke/fixtures/desktop-shell.ts owns test-scoped launch, startup readiness, diagnostics, clean-exit assertions and fallback cleanup. Every shell case gets a fresh process; there is no serial dependency or shared application state. Error arrays and startup-output checks now apply after every shell test, including intentional handler failure. Diagnostics JSON and attachments are captured per test. Cleanup attempts remaining resources and writes diagnostics even if an earlier close fails.
